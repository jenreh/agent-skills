# Agents plugin

Build AI agents with Pydantic AI, evaluate agents and LLM applications with
DeepEval, prepare datasets and pytest evaluation suites, and export OpenTelemetry
traces to Azure Monitor, Azure AI Foundry, or AWS X-Ray.
The plugin includes four shared skills.

## Included skills

| Skill | Description |
| --- | --- |
| [building-pydantic-ai-agents](skills/building-pydantic-ai-agents/SKILL.md) | Build agents with tools, capabilities, structured output, streaming, testing, and multi-agent patterns. Its references stay beside the skill. |
| [deepeval](skills/deepeval/SKILL.md) | Add evaluations, generate or reuse datasets, create pytest evaluation suites, and improve AI applications from evaluation results. |
| [deepeval-tracing](skills/deepeval-tracing/SKILL.md) | Instrument AI applications for Azure/AWS tracing, with optional local DeepEval evaluation support. |
| [deepeval-otel](skills/deepeval-otel/SKILL.md) | Export application and AI traces to a selectable Azure Monitor, Azure AI Foundry, or AWS X-Ray destination. |

`building-pydantic-ai-agents` covers agent design and code; use the DeepEval
skills to evaluate it and the tracing skills to observe it in Azure or AWS.
`deepeval-tracing` selects framework or manual OTel instrumentation;
`deepeval-otel` owns the Azure/AWS exporter and collector setup. Both tracing
workflows run without a Confident AI account. DeepEval is optional for local
component evaluation; native evaluation spans and cloud spans have separate roles.

## Use

See the [marketplace instructions](../../README.md#plugin-marketplace) to register the
`jenreh` marketplace first.

### GitHub Copilot

```sh
copilot plugin install jenreh-agents@jenreh
```

Start a new session and ask Copilot to use `building-pydantic-ai-agents` to build
an agent, or `deepeval` to add evaluations for an AI agent.

### Claude Code

```text
/plugin install jenreh-agents@jenreh
```

Invoke `/jenreh-agents:building-pydantic-ai-agents`, `/jenreh-agents:deepeval`,
`/jenreh-agents:deepeval-tracing`, or `/jenreh-agents:deepeval-otel` in a new session.

### Codex

Run [`scripts/add-skills.sh`](../../scripts/add-skills.sh); Codex picks the skills up from
`.agents/skills`.

## Format and requirements

The plugin uses the repository's [supported standards](../../README.md#supported-standards-and-clients):
[`plugin.json`](plugin.json) is a symlink to `.claude-plugin/plugin.json`, generated by
[`scripts/link-plugins.sh`](../../scripts/link-plugins.sh); one manifest serves Agent
Plugins 1.0.0, Copilot, and Claude Code. `skills/` contains shared Agent Skills. No MCP server, native commands or agents,
hooks, or service credentials are bundled.

For local evaluations, install DeepEval in the target project's Python environment:

```sh
pip install -U deepeval
```

Metrics and synthetic generation need model credentials. Evaluation data and
results can stay local. Both tracing skills use the following selectable cloud
destinations; no Confident AI login or API key is needed:

| `TRACE_DESTINATION` | Requirements |
| --- | --- |
| `azure-monitor` | Application Insights connection string and Azure Monitor exporter |
| `azure-ai-foundry` | Foundry project endpoint, Azure identity, linked Application Insights, and Foundry instrumentation |
| `aws-xray` | Reachable OTLP collector with X-Ray export and the collector's AWS region/IAM identity |

The export workflow supports general application and AI traces. It requires no
DeepEval package or Confident AI account. See its
[destination guide](skills/deepeval-otel/references/endpoint-and-exporter.md)
and [Python template](skills/deepeval-otel/templates/cloud_otel_setup.py).
Use the target project's existing dependencies and credentials; cloud ingestion
and evaluation/model calls may incur costs.

For example: `/jenreh-agents:deepeval-otel Export this application's traces to Azure
Monitor in general mode.` If only Azure is specified, the workflow asks whether
to use general Application Insights or the Foundry project's linked resource.
